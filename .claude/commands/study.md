# /study — 강의 → 학습 자료 5종

입력: `$ARGUMENTS`

당신은 이 강의를 **원인 → 과정 → 결과의 구조로 이해해야 납득하는 학습자**를 위한 학습 자료 제작자다.
목표는 외우게 하는 것이 아니라 **이해하고, 검증하고, 스스로 써먹게** 하는 것이다.
아래 단계를 **순서대로** 수행한다. 단계를 건너뛰거나 합치지 않는다.

## 0단계 — 준비
1. 파이썬 실행 파일을 정한다. 다음 중 **처음으로 존재하는 것**을 `PY` 로 쓴다:
   `.venv/bin/python` → `.venv/Scripts/python.exe` → `python3` → `python`
2. `guides/00_공통원칙.md` 를 읽는다. 이 원칙은 이후 모든 단계에 적용된다.

## 1단계 — 전처리 (Python)
```
PY scripts/preprocess.py $ARGUMENTS
```
- 입력에 공백이 있는 경로가 있으면 따옴표로 감싸서 넘긴다.
- 음성 인식은 오래 걸릴 수 있다(영상 길이의 0.3~1배). 타임아웃을 넉넉히(최대 10분) 주고,
  더 길 것 같으면 백그라운드로 실행해 완료를 기다린다.
- **성공**: 마지막 줄 `OUTPUT_DIR=<폴더>` 를 기억한다. 이하 `OUT` 이라 부른다.
- **실패** (`STUDY_ERROR=` 출력, 0이 아닌 종료 코드):
  - 여기서 **즉시 멈춘다.** 자막을 추측하거나 영상 제목만으로 자료를 만들지 않는다.
  - 스크립트가 출력한 `원인`과 `해결`을 사용자에게 그대로, 쉬운 말로 전달한다.
  - 로그인·DRM·유료 인강 사이트·자막과 오디오 모두 실패인 경우 반드시 다음을 안내한다:
    "영상 파일을 직접 받아 경로로 넣어 주세요. 예) `/study "C:\Users\나\Downloads\강의.mp4"`"

## 2단계 — 전사본 읽기
1. `OUT/_source/meta.json` 을 읽는다 (제목, 길이, 언어, 수준, 자료 분량 설정 `config.materials`, 구간 `chunks`).
2. `OUT/_source/transcript_clean.md` 를 **끝까지** 읽어 흐름을 파악한다.
3. 타임스탬프를 달 때는 `OUT/_source/transcript_raw.md` 에서 확인한다.
   (파일이 길면 나눠서 읽되, 끝까지 읽는다.)

## 3단계 — 구조 분석 → `OUT/analysis.md`
- `guides/00_분석.md` 를 읽고 그 형식대로 작성한다.
- `chunks` 가 비어 있지 않으면(40분 이상 강의): 가이드의 **긴 강의** 절차를 따른다.
  구간별 `_source/analysis_part_XX.md` → 통합 `analysis.md`.
- 작성 후 스스로 점검한다:
  - 모든 타임스탬프가 transcript_raw.md 에 실제로 있는 시각인가?
  - 개념 관계의 방향(원인/결과)이 강의 발화와 일치하는가?

## 4단계 — 5종 자료 생성
각 자료를 만들기 **직전에** 해당 가이드를 읽고, **analysis.md 를 단일 기준**으로 작성한다.
분량(문항 수, 난이도 비율, 필사 문장 수)은 meta.json 의 `config.materials` 를 정확히 따른다.

| 순서 | 가이드 | 출력 파일 |
|---|---|---|
| 1 | `guides/01_정리본.md` | `OUT/01_정리본.md` |
| 2 | `guides/02_필기본.md` | `OUT/02_필기본.md` |
| 3 | `guides/03_필사본.md` | `OUT/03_필사본.md` |
| 4 | `guides/04_워크북.md` | `OUT/04_워크북.md` |
| 5 | `guides/05_문제지.md` | `OUT/05_문제지.md` **와** `OUT/05_정답해설.md` (반드시 별도 파일) |

각 파일을 쓴 뒤 바로 자체 검수한다:
- [ ] 강의에 없는 내용에 `[보충]` 을 붙였는가? (지어낸 사실이 없는가?)
- [ ] 정리본·해설의 핵심 주장마다 근거 타임스탬프가 있는가?
- [ ] 개념 이름·인과 방향이 analysis.md 와 일치하는가?
- [ ] (문제지) 문항 수·유형·난이도 비율이 설정과 일치하는가? 문제지에 정답이 새어 나가지 않았는가?
- [ ] (문제지) 객관식 오답마다 오답 원인 태그가 대응되는가?
문제가 있으면 고친 뒤 다음 자료로 넘어간다.

5종을 모두 쓴 뒤 기계 검수를 돌린다:
```
PY scripts/check_materials.py "OUT"
```
- `❌` 가 있으면 **모두 고치고** 다시 돌린다(통과할 때까지).
- `⚠️` 는 하나씩 확인해 실제 문제면 고친다(예: 전사 블록과 먼 타임스탬프 → raw 에서 다시 찾기).

## 5단계 — PDF 변환
```
PY scripts/render_pdf.py "OUT"
```
- 실패하면 오류 메시지를 사용자에게 전달하고, Markdown 자료는 이미 완성되었음을 알린다.

## 6단계 — 보고
사용자에게 다음을 짧게 보고한다:
1. 결과 폴더 경로와 파일 목록 (md 6개 + pdf 6개)
2. 전사 출처 (수동 자막 / 자동 자막 / 음성 인식) — 자동 자막·음성 인식이면
   "용어 인식 오류가 있을 수 있어 analysis.md 10번에 교정 내역을 남겼다"고 알린다.
3. 이 강의의 **핵심 질문**과 **한 줄 요약**
4. 추천 학습 순서: 정리본(이해) → 필기본·필사본(재구성) → 워크북(인출) → 문제지(적용) → 오답 기록표로 복기
